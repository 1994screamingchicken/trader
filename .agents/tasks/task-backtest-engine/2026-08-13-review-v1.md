# Backtesting engine via polymorphic REST client override

Adds a complete backtesting subsystem that replays CSV OHLC data through existing Lua trading scripts unchanged. The key design choice is inheritance: `BacktestRestClient` extends `KrakenRestClient` (whose methods were made virtual), so `LuaEngine` receives it via its existing `shared_ptr<KrakenRestClient>` parameter and scripts call the same `trader.*` API. A `BacktestBroker` simulates order fills, tracks positions and P&L, and a `Performance` module computes metrics after the run. CLI flags (`--backtest --data --script --pair --balance --commission`) gate entry into backtest mode from `main.cpp`.

Watch for: Sell-side has no funds check, enabling unbounded short positions and negative cash (confirmed). `curl_global_init`/`curl_global_cleanup` called in the base `KrakenRestClient` constructor/destructor despite `BacktestRestClient` never making HTTP calls (confirmed). `candles_up_to()` copies the entire candle vector on every `get_ohlc()` call, O(n²) over a backtest run (confirmed). `std::stod` in CLI arg parsing throws on malformed input with no catch (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The broker handles long/short P&L tracking with average-entry-price bookkeeping, but enforces a funds check only on the buy side. Sells succeed unconditionally regardless of position or cash, so a script that sells without holding a position will open an uncollateralized short and drive cash positive by the notional amount—breaking equity accounting.

The `BacktestRestClient` constructor invokes the real `KrakenRestClient` constructor, which calls `curl_global_init(CURL_GLOBAL_ALL)`. The destructor calls `curl_global_cleanup()`. This is harmless in single-instance backtest mode but initializes libcurl for no reason and introduces a landmine if multiple engines are ever instantiated concurrently.

Performance-wise, every `get_ohlc()` call creates a new `vector<OhlcCandle>` from index 0 to the current candle. For 101 candles this is fine; for a year of minute data (~525k candles) this is quadratic in allocations and copies.

<details>
<summary>Issues (5)</summary>

1. **Unchecked sell-side in broker** — `execute_market_order` with `OrderSide::Sell` has no guard against selling more than the position or going short without margin. Add a check analogous to the buy-side cash check, or explicitly document that unlimited shorting is intentional.
2. **Unnecessary curl initialization** — `BacktestRestClient` inherits a constructor that calls `curl_global_init`. Either skip the base constructor's curl setup (add a protected constructor overload) or guard it behind the paper_trading/backtest flag.
3. **Quadratic candle copies in get_ohlc** — `candles_up_to(index)` returns a fresh vector copy each call. Return a `span` or `const_reference` + size, or cache the JSON result between calls at the same index.
4. **CLI argument parsing throws** — `std::stod(argv[++i])` for `--balance` and `--commission` will throw `std::invalid_argument` or `std::out_of_range` on bad input with no try/catch, producing an unhandled exception termination.
5. **Equity asymmetry on pair lookup** — `get_equity()` iterates `positions_` using the pair key stored at order time (e.g. "XBT/USD"), but the price map populated in `BacktestEngine::run()` stores both "XBT/USD" and "XBTUSD". If a Lua script places an order with a different pair format, the equity lookup silently misses it.

## Sell-side funds check missing in BacktestBroker

In `backtest_broker.cpp`, the buy path checks `cost > cash_` and returns false when funds are insufficient. The sell path has no equivalent guard:

```cpp
} else {  // Sell
    // If we're long, this is closing (partially or fully)
    if (current_pos > 0) { ... }

    double revenue = notional - commission;
    cash_ += revenue;
    positions_[pair] -= volume;
    ...
}
```

A script that issues a sell without holding the asset will create a negative position (short) while adding `notional - commission` to cash. This inflates cash without requiring collateral, so equity accounting becomes unreliable. The Sharpe ratio and drawdown metrics computed downstream depend on correct equity, so this cascades into misleading performance reports. Kraken itself rejects naked shorts without margin—this broker should either reject them or explicitly simulate a margin model.

## curl_global_init in backtest context

`KrakenRestClient::KrakenRestClient` always calls `curl_global_init(CURL_GLOBAL_ALL)`, and the destructor calls `curl_global_cleanup()`. The `BacktestRestClient` constructor passes a dummy `KrakenConfig` to the base class:

```cpp
BacktestRestClient::BacktestRestClient(DataFeed& feed, BacktestBroker& broker,
                                       const std::string& pair)
    : KrakenRestClient(make_dummy_config(), true),   // <-- calls curl_global_init
      feed_(feed), broker_(broker), pair_(pair) {}
```

If the engine is ever used in a test harness that constructs multiple `BacktestRestClient` instances, `curl_global_cleanup` from the first destruction will invalidate curl for subsequent instances. A protected constructor that skips curl setup, or a guard flag, would insulate against this.

## O(n²) candle copying in get_ohlc

`DataFeed::candles_up_to(size_t index)` creates a new vector each call:

```cpp
std::vector<OhlcCandle> DataFeed::candles_up_to(size_t index) const {
    return std::vector<OhlcCandle>(candles_.begin(), candles_.begin() + index + 1);
}
```

`BacktestRestClient::get_ohlc()` calls this, then iterates the result to build a JSON array. For 101 candles total, the cumulative copies are ~5,000 candles—trivial. For a year of hourly data (8,760 candles), it's ~38 million candle copies. For minute data, it's in the billions. Since `get_ohlc` is only called by scripts that explicitly request it (not every tick), the practical impact depends on strategy, but it's a scaling wall.

## CLI exception safety

```cpp
} else if (arg == "--balance" && i + 1 < argc) {
    bt_balance = std::stod(argv[++i]);
} else if (arg == "--commission" && i + 1 < argc) {
    bt_commission = std::stod(argv[++i]);
```

Passing `--balance foo` will terminate with an unhelpful `std::invalid_argument` what-string. Numeric parsing should either catch and report a user-friendly error, or use a strtod + errno pattern.

## Pair format fragility in equity computation

The engine computes equity by building a price map with both "XBT/USD" and "XBTUSD" variants:

```cpp
prices[config_.pair] = candle.close;           // "XBT/USD"
std::string no_slash = config_.pair;
no_slash.erase(std::remove(...), ...);
prices[no_slash] = candle.close;               // "XBTUSD"
```

But `BacktestBroker` stores positions keyed by whatever pair string the order used (`order.pair`). The `BacktestRestClient::place_order()` passes `order.pair` directly from the Lua script's `OrderRequest`. If a script constructs a pair string in yet another format (e.g., "XXBTZUSD" from Kraken's internal format), the position key won't match either price-map entry, and the equity calculation will silently exclude that position—reporting artificially low or high equity depending on position direction.
