# Backtesting engine: v2 review after fixes

The five issues from v1 are addressed: sell-side rejects naked shorts and clamps to position, `BacktestRestClient` uses a protected `SkipCurlInit` constructor that bypasses curl setup, `candles_up_to()` returns `std::span` instead of copying, CLI `std::stod` calls are wrapped in try/catch, and the equity price map now includes the Kraken internal pair format ("XXBTZUSD").

Watch for: `trader.sleep()` still calls `std::this_thread::sleep_for` in backtest mode, injecting real wall-clock delays into what should be a fast replay (confirmed). The Sharpe ratio calculation hardcodes an hourly-candle assumption (8760 periods/year) regardless of actual data interval (confirmed). Scripts that attempt sell-from-flat (like `simple_momentum.lua` when not holding a position) get silent failures that the script logs but nothing in the backtest report surfaces (confirmed).

**Verdict**: APPROVED

## High-level view

The `trader.sleep()` API still executes real sleeps (capped at 5 seconds) in backtest mode. No existing script currently calls it, so this is latent rather than active, but any strategy that uses sleep for throttling will be orders of magnitude slower than necessary during replay. A trivial fix would be to no-op sleep when the REST client is a `BacktestRestClient`, or pass a flag to LuaEngine indicating backtest mode.

The Sharpe ratio is annualized with `sqrt(8760)`, which assumes every candle is one hour. If a user feeds minute data (525,600 candles/year) or daily data (365 candles/year), the reported Sharpe will be wrong by a factor of ~8x or ~5x respectively. The data format carries no interval metadata, so either the CLI needs an `--interval` flag or the engine should infer it from timestamp deltas.

The sell-side guard prevents naked shorting, but `simple_momentum.lua` attempts sell-from-flat on the first downward signal. The broker rejects it, the script logs "SELL order failed", and the strategy becomes effectively long-only. A user reviewing the performance report won't see any indication that signals were generated but rejected—the trade count simply omits them. `BACKTESTING.md` should note that naked shorts are rejected.

## Real wall-clock sleep in backtest mode

`LuaEngine::lua_sleep` unconditionally sleeps:

```cpp
void LuaEngine::lua_sleep(int ms) {
    int capped = std::min(ms, 5000);
    std::this_thread::sleep_for(std::chrono::milliseconds(capped));
}
```

No existing bundled scripts call `trader.sleep()`, but any user strategy that throttles via sleep (common in live trading to avoid rate limits) will carry that dead time into backtest mode. For a 500-candle backtest where the script sleeps 1 second per tick, this adds 8+ minutes of wall-clock time that produces no useful work.

## Sharpe ratio annualization assumes hourly data

In `backtest_engine.cpp`:

```cpp
// Annualize: assume hourly candles -> 8760 periods per year
if (std_dev > 0) {
    r.sharpe_ratio = (mean_return / std_dev) * std::sqrt(8760.0);
}
```

The engine has no knowledge of the candle interval. The CSV format only carries timestamps, and while the delta between consecutive candles is implicit, the code never reads it. A user backtesting on 1-minute data will get a Sharpe inflated by roughly 8x. The fix is either to accept `--interval` as minutes and compute `periods_per_year = 525600 / interval`, or to compute the median delta between the first N candle timestamps and derive the annualization factor automatically.

## Script-broker behavioral mismatch on sell-from-flat

`simple_momentum.lua` transitions directly from "flat" to issuing a sell order when it detects a negative momentum signal (the `state.position ~= "short"` guard passes when position is "flat"). The broker's new guard rejects this:

```cpp
if (current_pos <= 0) {
    return false;  // Cannot sell without a long position
}
```

The script handles the failure gracefully (logs "SELL order failed", doesn't update position state), so no crash or accounting error occurs. The strategy becomes effectively long-only in backtest. The documentation in `BACKTESTING.md` notes that "Market orders fill at the candle close price" but doesn't mention that naked shorts are rejected—adding a note about this constraint would help users understand why their short-capable strategies show no short trades.
